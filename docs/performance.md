# Performance

Benchmarks compare the native Delphi implementation with the pinned LZMA SDK
26.06 and xz-utils tools used by the test suite.

The SDK target does not imply throughput, compressed-size, CPU, or memory
parity. Current claims require matched settings, the same input corpus, and
repeated measurements from the source revision being evaluated.
Regenerate detailed benchmark data with:

```powershell
.\tests\install-qa-tools.ps1
.\tests\run-performance.ps1 -WorkRoot <SSD_WORKROOT>
```

The benchmark work root must be an owned scratch directory outside the
repository. Use a local SSD path for normal runs. A RAM-backed path can be used
only when explicitly selected by `-RamWorkRoot`.

`quick` does not run `tests/run-performance.ps1`. Release and soak modes run
`tests/run-performance.ps1` and own the full performance evidence.

## Outputs

`tests/run-performance.ps1` writes data-only files under ignored
`artifacts/perf/`:

- `lzma2-benchmark.csv`
- `lzma2-benchmark.json`
- `lzma2-benchmark.samples.csv`
- `lzma2-benchmark.summary.json`

The benchmark artifacts record:

- input and output sizes;
- compression ratio;
- elapsed time;
- throughput in MiB/s and MB/s;
- thread count;
- dictionary size;
- check type;
- CPU time and its measurement status;
- peak process working set and private commit, with measurement status;
- tool versions and normalized command options.

Graph images are not generated by release validation. If charts are needed,
generate them separately from the data files.

## Notes

Compression output is format-compatible, but not expected to be byte-identical
to the SDK output. Compare compressed size, ratio, throughput, and successful
round trips instead.

The CLI `benchmark` command reports `ratio = inputBytes / compressedBytes`;
higher is better. The performance artifacts use
`compressionRatio = compressedBytes / inputBytes`; lower is better. The CLI
uses decimal MB/s, while the artifact data includes explicitly named MB/s and
MiB/s fields. Compare the same ratio direction and throughput unit.

Short smoke runs can be noisy. Use release-size corpora and repeated samples
when making performance claims.

GitHub run id/SHA/ref/attempt and workflow name are required when the manifest contains GitHub Actions context.
